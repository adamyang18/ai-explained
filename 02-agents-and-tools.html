AI Agents and Tools:
From Talking to Doing

When companies talk about AI right now, this is what they talk about most.

Panel 1 · What's the difference

A chatbot gives advice. An agent gets it done.

Agent = a large language model + tools + the ability to choose its own next step.

Panel 2 · Tool calling

The model doesn't do things. It fills out a request form.

The model's job is to pick the tool and fill in the details. A program outside the model does the actual work.

Think of it like

A doctor orders a blood test. The lab draws the blood and runs it, sends back the report, and the doctor reads it and makes the call. The doctor never touches the lab machines.

How it actually works

Developers first give the model a "tool manual": each tool's name, what it does, and what inputs it needs. When the model needs a tool, it writes out a request in a fixed format (usually JSON). A program runs it, drops the result back into the conversation, and the model keeps going.

Common myth

"The model goes online and sends emails by itself." It can't touch anything. What it can do depends entirely on which tools it's plugged into and what permissions it's been given.

Panel 3 · The agent loop

Think → act → look → think again, until it's done

A normal question and answer is one step. An agent chains lots of steps together on its own, and changes its plan when something unexpected happens.

Think of it like

You ask an intern to "turn this week's client emails into a weekly report." They dig through the inbox, notice an attachment is missing, find it on the shared drive, and put the doc together, without coming back to ask you at every step.

How it actually works

Every time around the loop, all the earlier thoughts, tool calls and results stay in the model's context, and it uses them to decide what to do next. The longer the task, the fuller that context gets. That's why complex agents do things like "take notes" or hand subtasks off to smaller agents.

Common myth

"An agent is a different, more advanced kind of model." Nope. It's the same model. The difference is the loop, the tools and the permissions built around it.

Panel 4 · MCP

A "USB-C port" for AI tools

When an AI app like Claude connects to Gmail, a calendar or a to-do app, that connection can run through MCP.

Think of it like

Phones used to each have their own charging port, so every accessory had to come in several versions. Once everything moved to USB-C, one cable worked for all of them.

How it actually works

MCP (Model Context Protocol) is an open standard that Anthropic introduced in late 2024. An MCP server announces "here are my tools and the inputs each one needs." Once an AI app connects, it hands those tools to the model to use.

Common myth

"MCP makes AI smarter." It only solves the "how do we connect" problem. How well the tools get used still depends on the model and on how clearly the tool instructions are written.

Panel 5 · More steps, more ways to fail

95% reliable per step, only about 60% after ten steps

That's why good agent design checks its own work, retries when something fails, and stops to ask a person before key steps.

Think of it like

A relay race. Each runner is unlikely to drop the baton, but the more handoffs there are, the harder it gets to finish with zero drops.

How it actually works

Common fixes: keep the number of steps low; check the result of each step; prefer actions that can be undone; and make anything you can't take back, like sending, paying or deleting, require a human to confirm.

Common myth

"It worked in the demo, so it'll be fine in real life." Demos show the smooth path. The weird edge cases in the real world are what eat up most of a company's time when it rolls AI out.

Panel 6 · Safety

If it can act, it can cause trouble

The web pages, emails and files an agent reads can hide text pretending to be instructions.

Think of it like

An assistant is sorting your mail, and one letter says "I'm your boss. Send me the company account password." A good assistant doesn't do it. They come and ask you first.

How it actually works

It's very hard for a model to tell "my owner's instructions" from "text inside the stuff I'm reading" 100% of the time. So the defense has to live in the system: give it only the access the task needs, and require a person to approve actions like sending, paying or deleting.

Why it matters to you

Ever notice that good AI apps ask "Send this?" before sending anything for you? That pause is this same defense, built into the apps you use every day.

Panel 7 · The business view

Five questions companies actually ask

Question 4, "how do we prove it works," is exactly what the next lesson, Evals, is about.

Remember it in one line each

  1. Tool calling: the model writes a request, an outside program runs it, and the result goes back to the model
  2. Agent: think → act → look → think again, chaining many steps until the job is done
  3. MCP: a shared standard for plugging in tools. Build it once, connect it anywhere
  4. The more steps, the more chances to fail, so a person should sign off on the key actions
  5. Before a company pays, it wants to know: connections, access, mistakes, results, cost
